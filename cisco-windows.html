🪟 Windows — Сетевые команды

📌 Как пользоваться

Команды выполняются в командной строке Windows (cmd) от имени администратора (для route и netstat -b). Каждая карточка — конкретная задача: краткое описание, схема (ваша локальная сеть), пример команд с кнопкой «Копировать».

Карта сети (общая): ПК A = 192.168.1.2, ПК B = 192.168.1.3, шлюз (модем) = 192.168.1.1, локальная сеть = 192.168.1.0/24.

1. route add — VPN + локальная сеть (вижу VPN, не вижу ПК B)
📌 Кратко
На ПК A поднят VPN. После подключения ПК A перестаёт видеть ПК B (192.168.1.3) в локальной сети. Причина: VPN «забирает» весь трафик (0.0.0.0/0) через VPN-шлюз. Решение — постоянный маршрут в локальную сеть через модем (192.168.1.1).
🗺 Схема
[ПК A: 192.168.1.2] --- (LAN 192.168.1.0/24) --- [ПК B: 192.168.1.3] | +--- VPN-туннель --- [VPN-сервер] | Шлюз (модем): 192.168.1.1 next-hop для LAN = 192.168.1.1 (локальный шлюз)
⚙️ Пример (cmd от администратора)
:: Добавить постоянный маршрут в локальную сеть через модем
route -p add 192.168.1.0 mask 255.255.255.0 192.168.1.1

:: Проверить таблицу маршрутизации
route print

:: Удалить (если больше не нужен)
route delete 192.168.1.0 mask 255.255.255.0
⚠️ Грабли
Без -p маршрут исчезнет после перезагрузки. route add требует прав администратора. Если VPN-клиент перезаписывает таблицу — настройте split tunneling в клиенте.
2. ipconfig — проверка IP, шлюза, DNS
📌 Кратко
ipconfig показывает текущие IP-адреса, маску, шлюз, DNS. ipconfig /all — подробно (MAC, DHCP, аренда). ipconfig /release и /renew — сбросить/получить IP по DHCP.
🗺 Схема
[ПК A] --- (LAN) --- [Модем: 192.168.1.1] --- [Интернет] | IP: 192.168.1.2 Mask: 255.255.255.0 Gateway: 192.168.1.1 DNS: 8.8.8.8
⚙️ Пример (cmd)
:: Краткая информация
ipconfig

:: Подробная (MAC, DHCP, DNS)
ipconfig /all

:: Сбросить и получить IP по DHCP
ipconfig /release
ipconfig /renew

:: Очистить DNS-кэш
ipconfig /flushdns
⚠️ Грабли
Если IP начинается на 169.254.x.x — DHCP не ответил (APIPA). Проверьте, что DHCP-сервер доступен.
3. ping — проверка связности
📌 Кратко
ping проверяет, доходит ли пакет до узла (ICMP Echo). Если пинг не идёт — проблема на L3 (маршрут, шлюз, firewall). Если пинг идёт, а сервис не работает — проблема выше (порт, DNS, приложение).
🗺 Схема
[ПК A: 192.168.1.2] --- [Модем: 192.168.1.1] --- [ПК B: 192.168.1.3] | | ping 192.168.1.1 (шлюз) ping 192.168.1.3 (сосед) ping 8.8.8.8 (интернет) Порядок: сначала шлюз, потом сосед, потом интернет.
⚙️ Пример (cmd)
:: Проверить шлюз
ping 192.168.1.1

:: Проверить соседа
ping 192.168.1.3

:: Проверить интернет (Google DNS)
ping 8.8.8.8

:: Бесконечный пинг (Ctrl+C для остановки)
ping 8.8.8.8 -t

:: 100 пакетов, размер 64 байта
ping 8.8.8.8 -n 100 -l 64
⚠️ Грабли
Если пинг не идёт, но IP настроен — проверьте маску (не /32?), шлюз, firewall на ПК B (может блокировать ICMP).
4. tracert — трассировка маршрута
📌 Кратко
tracert показывает, через какие роутеры проходит пакет до цели. Если на каком-то хопе * * * — там проблема (или ICMP заблокирован). Помогает понять, где «ломается» сеть.
🗺 Схема
[ПК A: 192.168.1.2] → [Модем: 192.168.1.1] → [ISP] → [Google 8.8.8.8] tracert 8.8.8.8: 1 192.168.1.1 2 10.0.0.1 (ISP) 3 8.8.8.8
⚙️ Пример (cmd)
:: Трассировка до Google DNS
tracert 8.8.8.8

:: Трассировка до соседа
tracert 192.168.1.3

:: Не резолвить имена (быстрее)
tracert -d 8.8.8.8

:: Максимум 15 хопов
tracert -h 15 8.8.8.8
⚠️ Грабли
* * * — не всегда проблема: некоторые роутеры блокируют ICMP TTL. Если последний хоп — цель, а до неё * * * — возможно, ICMP заблокирован на цели.
5. nslookup — проверка DNS
📌 Кратко
nslookup проверяет, резолвится ли имя в IP. Если сайт «не открывается», а пинг по IP идёт — проблема в DNS. nslookup покажет, какой DNS-сервер отвечает и что он вернул.
🗺 Схема
[ПК A] --- [DNS: 8.8.8.8] --- [google.com → 142.250.185.78] nslookup google.com: Server: 8.8.8.8 Address: 142.250.185.78
⚙️ Пример (cmd)
:: Проверить резолвинг имени
nslookup google.com

:: Проверить через конкретный DNS
nslookup google.com 8.8.8.8

:: Обратный резолвинг (IP → имя)
nslookup 8.8.8.8
⚠️ Грабли
Если nslookup возвращает «Server: unknown» — DNS-сервер недоступен. Если возвращает «Non-existent domain» — имя не существует (опечатка или DNS-фильтр).
6. netstat — активные соединения и порты
📌 Кратко
netstat показывает активные TCP/UDP-соединения, listening-порты, PID процессов. Помогает понять, «кто держит порт 80» или «куда идёт трафик».
🗺 Схема
[ПК A] --- TCP 192.168.1.2:52341 → 142.250.185.78:443 (ESTABLISHED) | netstat -an Proto Local Address Foreign Address State TCP 192.168.1.2:52341 142.250.185.78:443 ESTABLISHED
⚙️ Пример (cmd)
:: Все соединения (числами)
netstat -an

:: С PID процессов
netstat -ano

:: Только listening-порты
netstat -an | find "LISTENING"

:: Кто держит порт 80 (нужен PID из netstat -ano)
tasklist | find "PID"
⚠️ Грабли
netstat -b (с именами процессов) требует прав администратора. ESTABLISHED — соединение активно, TIME_WAIT — закрывается (норма), LISTENING — порт открыт.
