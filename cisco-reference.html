VLAN

L2VLANСегментация

Зачем: Логически делит один физический свитч на несколько независимых broadcast-доменов. Клиенты разных VLAN не видят трафик друг друга (без L3-маршрутизации), что повышает безопасность и снижает нагрузку от broadcast-штормов. Как работает: Каждый кадр внутри свитча помечается VLAN-ID (12 бит, до 4094 VLAN). Порт доступа (access) принадлежит одному VLAN; trunk передаёт несколько VLAN с тегами 802.1Q. Как настроить: vlan X — создать VLAN, name — имя, затем порт switchport access vlan X. Для trunk — switchport mode trunk + allowed vlan. Проверка: show vlan brief — список VLAN и портов; show interfaces switchport — детали по порту.

PC1 ──┐ ├── [Switch] ── VLAN 100 (Users) ← broadcast-домен 1 PC2 ──┘ PC3 ──┐ ├── [Switch] ── VLAN 200 (Voice) ← broadcast-домен 2 PC4 ──┘
vlan 100
 name Users
vlan 200
 name Voice
interface f0/10
 switchport mode access
 switchport access vlan 100
 exit
interface f0/11
 switchport mode access
 switchport access vlan 200
 exit
show vlan brief

Trunk (802.1Q)

L2Trunk802.1Q

Зачем: Передаёт трафик нескольких VLAN между двумя свитчами (или свитч ↔ роутер) по одному кабелю. Без trunk пришлось бы тянуть отдельный кабель на каждый VLAN — это дорого и неудобно. Как работает: Каждый кадр тегируется VLAN-ID (4 байта 802.1Q). Исключение — Native VLAN: её трафик идёт без тега (по умолчанию VLAN 1). Безопасность: Native VLAN по умолчанию = VLAN 1. Её меняют (например, на 99), чтобы злоумышленник не мог «прыгнуть» между VLAN через double-tagging. Проверка: show interfaces trunk — какие порты в trunk, какие VLAN разрешены, какая native VLAN.

Switch A ═══════════ trunk ═══════════════ Switch B [VLAN 100 | VLAN 200 | VLAN 300] каждый кадр несёт тег 802.1Q (кроме native)
interface f0/1
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 1,100,102-108
 exit
show interfaces trunk

EtherChannel (LACP / PAgP)

L2АгрегацияLACPPAgP

Зачем: Объединяет несколько физических линков между двумя устройствами в один логический (Port-Channel). Даёт суммарную пропускную способность и отказоустойчивость: если один кабель порвётся, канал продолжит работать (трафик пойдёт через остальные). Протоколы: LACP (IEEE 802.3ad) — режимы active/passive. PAgP (Cisco) — desirable/auto. Режим on — без протокола (не рекомендуется, нет проверки ошибок). Правило: Все порты в канале должны иметь одинаковые speed/duplex, режим (trunk/access) и разрешённые VLAN. Иначе канал не соберётся. Балансировка: трафик распределяется по линкам на основе хеша (по MAC, IP или портам). Настраивается глобально: port-channel load-balance src-dst-mac. Проверка: show etherchannel summary — ищем статус SU (Switched, Up) и флаг P (In Port-Channel).

Switch A ═══════ Port-Channel 1 ═══════ Switch B 4 физических линка (Fa0/1-4), LACP active суммарно 400 Мбит/с + резервирование
interface range f0/1 - 4
 shutdown
 channel-group 1 mode active
 switchport trunk encapsulation dot1q
 switchport mode trunk
 speed 100
 duplex full
 no shutdown
 exit
interface port-channel 1
 switchport mode trunk
 exit
show etherchannel summary

STP / Rapid-PVST+

L2STPLoop protection

Зачем: Защищает от петель на L2. Если между свитчами несколько линков, STP выбирает один Root Bridge и блокирует избыточные порты (Altn BLK), чтобы кадры не ходили по кругу бесконечно. Как работает: Выбирается Root Bridge (наименьший Bridge ID = priority + MAC). Затем каждый свитч выбирает Root Port (ближайший к корню) и блокирует остальные. Ускорение: portfast — порт к ПК сразу в Forwarding (не ждёт 30 сек). bpduguard — отключает порт, если на него пришёл BPDU (защита от подключения свитча к порту ПК). Проверка: show spanning-tree vlan 1 — ищем «This bridge is the root».

[Switch A] Root (priority 24576) / \ [Switch B] [Switch C] \ / [Switch D] ← один порт Altn BLK
spanning-tree mode rapid-pvst
spanning-tree vlan 1,100,102-108 priority 24576
interface f0/10
 spanning-tree portfast
 spanning-tree bpduguard enable
 exit
show spanning-tree vlan 1

MSTP

L2STPMSTP

Зачем: Группирует VLAN в инстансы (instance). Позволяет балансировать нагрузку: один свитч — root для instance 1, другой — для instance 2. В Rapid-PVST+ так нельзя (каждый VLAN = отдельный инстанс). Как работает: Все свитчи должны иметь одинаковое имя региона (region name), ревизию и маппинг VLAN → instance. Иначе они не «увидят» друг друга. Проверка: show spanning-tree mst 1 — ищем «This bridge is the root».

Instance 1 (VLAN 100,102,104) → Switch A Root Instance 2 (VLAN 105-108) → Switch B Root трафик распределён между ядровыми свитчами
spanning-tree mode mst
spanning-tree mst configuration
 name LAB
 instance 1 vlan 100,102,104
 instance 2 vlan 105,106,107,108
 exit
spanning-tree mst 1 root primary
spanning-tree mst 2 root secondary
show spanning-tree mst 1

SVI (шлюз для VLAN)

L3SVIШлюз

Зачем: Виртуальный интерфейс на L3-свитче, который служит шлюзом для VLAN. Позволяет маршрутизировать трафик между VLAN внутри одного свитча (без внешнего роутера). Как работает: interface VlanX + ip address. Требует ip routing глобально на свитче. Важно: SVI поднимается только если в VLAN есть хотя бы один активный порт (или trunk). Иначе статус down/down. Проверка: show ip interface brief — статус up/up.

VLAN 100: 192.168.1.0/24 → SVI Vlan100 = .254 (шлюз) VLAN 200: 192.168.2.0/24 → SVI Vlan200 = .254 (шлюз) свитч маршрутизирует между VLAN
ip routing
interface Vlan100
 ip address 192.168.1.254 255.255.255.0
 no shutdown
 exit
interface Vlan200
 ip address 192.168.2.254 255.255.255.0
 no shutdown
 exit
show ip interface brief

Статическая маршрутизация

L3RouteStatic

Зачем: Вручную задать маршрут до сети через next-hop (IP соседа) или выходной интерфейс. Default route (0.0.0.0/0) — маршрут «по умолчанию», используется, когда нет более конкретного. AD (Administrative Distance): приоритет источника маршрута. Static = 1, EIGRP = 90, OSPF = 110. Чем меньше AD, тем приоритетнее. Резервирование: можно прописать два default route с разным AD — второй станет резервным (активируется при падении первого). Проверка: show ip route (статика — метка «S», default — «S*»).

Router 1 ── 192.168.1.0/24 ── Router 2 ── 0.0.0.0/0 ── ISP статика: ip route 192.168.2.0/24 via Router 2 default: ip route 0.0.0.0/0 via ISP
ip route 192.168.2.0 255.255.255.0 192.168.1.2
ip route 0.0.0.0 0.0.0.0 10.0.0.1
ip route 0.0.0.0 0.0.0.0 10.0.0.2 200
show ip route

OSPFv2

L3OSPFLink-State

Принцип: Link-State протокол. Каждый роутер строит полную карту сети (LSDB) и вычисляет кратчайшие пути по алгоритму Дейкстры. Быстро сходится, не рассылает всю таблицу маршрутизации (только изменения). Иерархия (Areas): Area 0 (Backbone) — ядро. Остальные зоны (Area 1, 2...) подключаются к Area 0 через ABR (Area Border Router). Это снижает нагрузку на CPU и стабилизирует сеть (изменения в Area 1 не «трясут» Area 2). Соседство: требует совпадения Area ID, Hello/Dead таймеров, пароля, MTU, типа сети. Если соседство «залипло» в EXSTART/EXCHANGE — почти всегда проблема в MTU. DR/BDR: в широковещательных сетях выбирается Designated Router и Backup — чтобы не создавать полную mesh-сеть соседства (N×(N−1)/2). DROther устанавливают соседство только с DR/BDR. Метрика: Cost = 10^8 / Bandwidth (чем выше скорость, тем ниже cost). Можно менять вручную: ip ospf cost X на интерфейсе. Типы LSA (запомнить): Type 1 — Router (внутри Area), Type 2 — Network (от DR), Type 3 — Summary (от ABR), Type 4 — ASBR Summary, Type 5 — External (от ASBR). Типичные ошибки: (1) не совпал MTU на интерфейсах — соседство «висит» в EXSTART; (2) не совпал Area ID — соседство не встаёт; (3) забыли area 0 authentication — соседство не встаёт; (4) не совпал Hello/Dead таймер — соседство не встаёт. Связанные темы: Redistribution, OSPFv3, HSRP (для резервирования шлюза). Проверка: show ip ospf neighbor (FULL), show ip ospf database (LSDB), show ip route ospf (метка «O»).

Area 0 (ядро) / \ [ABR] [ABR] | | Area 1 Area 2 (Switch C) (Switch D, Switch E)
router ospf 1
 router-id 1.1.1.1
 network 192.168.1.0 0.0.0.255 area 0
 network 192.168.5.0 0.0.0.255 area 1
 area 0 authentication
 exit
interface f0/0
 ip ospf authentication-key gro1ch21
 exit
show ip ospf neighbor
show ip route ospf

EIGRP

L3EIGRPHybrid

Принцип: Гибридный протокол (Distance Vector + Link State). Использует алгоритм DUAL для быстрой сходимости. Считается «проприетарным Cisco» (хотя с 2013 открыт по RFC 7868). Как работает: Номер AS (Autonomous System) должен совпадать у соседей. no auto-summary отключает автоматическое суммирование сетей на границе класса. Термины DUAL: Successor — основной маршрут (лучший). Feasible Successor — резервный маршрут (готов сразу, без пересчёта). Feasible Distance — метрика до сети. Reported Distance — метрика, которую сообщил сосед. Метрика: bandwidth + delay (по умолчанию), опционально load/reliability. Формула: 256 × (10^7 / min bandwidth + сумма delay). Типичные ошибки: (1) не совпал номер AS — соседство не встаёт; (2) разные K-значения (K1–K5) — соседство не встаёт; (3) не отключили auto-summary — маршруты «схлопываются» на классовой границе. Связанные темы: Redistribution (EIGRP ↔ OSPF), BGP (стык с провайдером). Проверка: show ip eigrp neighbors (статус UP), show ip eigrp topology (Successor/Feasible Successor), show ip route eigrp (метка «D»).

Router 2 (AS 100) ─── Switch D (AS 100) EIGRP neighbor UP обмен маршрутами внутри AS 100
router eigrp 100
 network 192.168.1.0 0.0.0.255
 no auto-summary
 exit
show ip eigrp neighbors
show ip route eigrp

BGP (eBGP)

L3BGPWAN

Принцип: Протокол маршрутизации между автономными системами (AS). Используется для стыка с провайдером (eBGP) или внутри крупной сети (iBGP). Работает поверх TCP (порт 179). eBGP vs iBGP: eBGP — между разными AS (ISP ↔ клиент). iBGP — внутри одной AS (между граничными роутерами). iBGP требует full-mesh или route reflector. Как работает: neighbor X remote-as Y — установить соседство. network X mask Y — анонсировать сеть. BGP не «находит» сети автоматически — их нужно явно анонсировать или переливать из IGP (через redistribute). Атрибуты (запомнить порядок): Weight (Cisco) → Local Preference → Locally Originated → AS-Path (короче = лучше) → Origin → MED → eBGP > iBGP → IGP metric. Типичные ошибки: (1) не совпал remote-as — соседство не встаёт; (2) нет маршрута до neighbor — соседство «висит» в Active; (3) анонсировали сеть, которой нет в таблице маршрутизации — BGP её не анонсирует; (4) забыли next-hop-self на iBGP — соседи не видят next-hop. Связанные темы: Redistribution, Route Filtering (prefix-list, route-map). Проверка: show ip bgp summary (соседи в Established), show ip bgp (таблица BGP), show ip bgp neighbors X advertised-routes (что мы анонсируем).

ISP (AS 65001) ═══ eBGP ═══ Router 1 (AS 65002) │ внутренняя сеть (OSPF/EIGRP)
router bgp 65002
 neighbor 10.0.0.1 remote-as 65001
 network 192.168.1.0 mask 255.255.255.0
 exit
show ip bgp summary
show ip bgp

Redistribution

L3RedistributionOSPF ↔ EIGRP

Зачем: Перелив маршрутов между разными протоколами (OSPF → EIGRP, EIGRP → OSPF, Static → OSPF, BGP → OSPF). Нужен, когда сеть состоит из двух доменов маршрутизации. Как работает: На граничном роутере (ASBR) указывается redistribute <протокол>. Для OSPF обязательно subnets (иначе передадутся только классовые сети). Для EIGRP — metric (5 параметров: bandwidth, delay, reliability, load, MTU). AD (Administrative Distance): при переливе маршрутов AD меняется. Внешние OSPF (O E2) = 110, внешние EIGRP (D EX) = 170. Это может привести к «петлям» — используйте route-map/distribute-list для фильтрации. Типичные ошибки: (1) забыли subnets — передались только классовые сети; (2) не указали metric для EIGRP — маршруты не передаются; (3) петля между OSPF и EIGRP — нужен route-map для фильтрации. Связанные темы: OSPF, EIGRP, BGP, Route Filtering. Проверка: show ip route (маршруты «O E2» — внешние OSPF, «D EX» — внешние EIGRP), show ip protocols (что и откуда переливается).

OSPF (Area 0) ── Router 2 (ASBR) ── EIGRP (AS 100) redistribution в обе стороны (с metric и subnets)
router ospf 1222
 redistribute eigrp 100 subnets
 exit
router eigrp 100
 redistribute ospf 1222 metric 10000 100 255 1 1500
 exit
show ip route

HSRP

L3FHRPРезервирование

Принцип: Два роутера делят один виртуальный IP (шлюз для клиентов). Клиенты настраивают этот IP как шлюз и не знают, какой роутер активен. Active / Standby: больший приоритет → Active. Если Active падает, Standby мгновенно перехватывает виртуальный IP. preempt позволяет вернуть роль Active после восстановления (иначе бывший Active останется Standby). version 2: поддержка IPv6 и больше групп (0–4095). version 1 — только IPv4, группы 0–255. Виртуальный MAC: 0000.0c07.acXX, где XX — номер группы в hex. Например, группа 1 = 0000.0c07.ac01. Типичные ошибки: (1) не совпал номер группы — два HSRP-процесса не видят друг друга; (2) забыли preempt — после восстановления Active остаётся Standby; (3) не совпал виртуальный IP — клиенты ходят через разные шлюзы. Отличие от VRRP: HSRP — Cisco-проприетарный; VRRP — открытый стандарт (IEEE 3768). В мультивендорной сети — VRRP. Связанные темы: VRRP, GLBP, OSPF (для маршрутизации к HSRP-шлюзу). Проверка: show standby brief (Active/Standby, виртуальный IP), show standby (детали).

Router 1 (Active, prio 150) ═══ Router 2 (Standby, prio 100) ╲ ╱ Виртуальный IP: 192.168.1.2 (клиенты используют его как шлюз)
interface f0/0
 standby version 2
 standby 1 ip 192.168.1.2
 standby 1 priority 150
 standby 1 preempt
 exit
show standby brief

VRRP

L3FHRPIEEE

Принцип: Открытый стандарт (IEEE 3768), аналог HSRP. Master/Backup, виртуальный IP + виртуальный MAC. Используется в мультивендорных сетях (не только Cisco). Отличие от HSRP: в VRRP Master — это реальный роутер с виртуальным IP; в HSRP Active — тоже реальный, но виртуальный MAC другой. Приоритет: 1–254 (по умолчанию 100). Больший → Master. Проверка: show vrrp.

Router 1 (Master) ═══ Router 2 (Backup) Виртуальный IP: 192.168.1.2 (стандарт IEEE — работает с любым вендором)
interface f0/0
 vrrp 1 ip 192.168.1.2
 vrrp 1 priority 150
 vrrp 1 preempt
 exit
show vrrp

GLBP

L3FHRPCisco

Принцип: Проприетарный протокол Cisco. В отличие от HSRP/VRRP, не просто резервирует шлюз, а балансирует нагрузку между несколькими роутерами. AVG / AVF: AVG (Active Virtual Gateway) — главный, раздаёт виртуальные MAC. AVF (Active Virtual Forwarder) — реальные роутеры, каждый обслуживает часть трафика. Балансировка: round-robin, weighted, host-dependent. Проверка: show glbp.

Router 1 (AVG) ──┐ Router 2 (AVF) ──┼── Виртуальный IP: 192.168.1.2 Router 3 (AVF) ──┘ (нагрузка распределена между AVF)
interface f0/0
 glbp 1 ip 192.168.1.2
 glbp 1 priority 150
 glbp 1 preempt
 glbp 1 load-balancing round-robin
 exit
show glbp

NAT / PAT

L3NATPAT

Зачем: Позволяет устройствам с приватными IP (192.168.x.x) выходить в интернет через один публичный IP. Экономит IPv4-адреса и скрывает внутреннюю структуру сети. Типы: Static NAT (1 к 1) — для серверов. Dynamic NAT (пул) — редко. PAT / Overload (много внутренних → 1 внешний, разные порты) — самый частый вариант. Как работает: На внутреннем интерфейсе — ip nat inside, на внешнем — ip nat outside. ACL определяет, какие адреса транслировать. PAT меняет source IP + source port, ведёт таблицу трансляций. Термины: Inside Local (внутренний IP до NAT), Inside Global (внутренний IP после NAT), Outside Local (внешний IP до NAT), Outside Global (внешний IP после NAT). Типичные ошибки: (1) забыли ip nat inside / ip nat outside — трансляция не работает; (2) ACL не покрывает нужные адреса — трансляция не работает; (3) конфликт с IPsec — NAT «съедает» пакеты до шифрования (нужен deny ip для VPN-трафика). Связанные темы: Static NAT (port forwarding), IPsec (NAT-T), ACL. Проверка: show ip nat translations (таблица активных трансляций), show ip nat statistics (счётчики).

LAN 192.168.0.0/24 ── [Router NAT] ── ISP 30.30.30.31 (много внутренних IP) (один внешний IP, разные порты)
interface f0/0
 ip nat inside
 exit
interface f0/1
 ip nat outside
 exit
ip access-list extended NAT
 permit ip 192.168.0.0 0.0.0.255 any
 exit
ip nat inside source list NAT interface f0/1 overload
show ip nat translations

Static NAT

L3NATStatic

Зачем: Постоянная трансляция «один-к-одному»: внутренний IP всегда соответствует внешнему. Нужна для серверов, к которым обращаются извне (веб, почта, FTP). Как работает: ip nat inside source static <внутренний> <внешний>. Внешний IP может быть адресом интерфейса. Port Forwarding: частный случай Static NAT — проброс конкретного порта (например, TCP 80) на внутренний сервер. Проверка: show ip nat translations (запись типа «---»).

Web-сервер 192.168.3.53:80 ↕ (static NAT) Внешний IP 30.30.30.31:80 ← клиенты из интернета
ip nat inside source static 192.168.3.53 30.30.30.31
ip nat inside source static tcp 192.168.3.53 80 interface f0/1 80
show ip nat translations

ACL Standard

SecurityACLStandard

Принцип: Фильтрует трафик только по Source IP (номера 1–99). Просто, но грубо: нельзя указать destination или порт. Где применять: Ближе к получателю (чтобы не блокировать трафик раньше времени). VTY: на линиях line vty применяется через access-class — ограничивает, кто может подключаться по Telnet/SSH. Правило: В конце ACL неявный deny any. Поэтому всегда нужен хотя бы один permit.

[PC1 10.0.3.2] ── [Switch] ── [Router 1] ── [Server 192.168.3.10] access-list 1 deny 10.0.3.2 access-list 1 permit any → PC1 не видит сервер, остальные видят
access-list 10 permit 4.4.4.4
line vty 0 4
 access-class 10 in
 exit
access-list 1 deny 10.0.3.2
access-list 1 permit any
interface f0/1
 ip access-group 1 out
 exit
show ip access-lists

ACL Extended

SecurityACLExtended

IPsec (Site-to-Site)

SecurityVPNIPsec

Зачем: Шифрование трафика между двумя офисами через интернет. Защищает от прослушивания и подмены. Компоненты: IKE (фаза 1 — согласование ключей), IPsec (фаза 2 — шифрование трафика). ESP — шифрование + аутентификация, AH — только аутентификация (без шифрования, редко используется). Режимы: Transport (хост-хост, шифрует только payload), Tunnel (сеть-сеть, шифрует весь пакет — используется в site-to-site). IKEv1 vs IKEv2: IKEv1 — старый (main/aggressive mode). IKEv2 — новый, быстрее, поддерживает MOBIKE (мобильность). В новых сетях — IKEv2. Типичные ошибки: (1) не совпали политики IKE (шифрование, хеш, DH-группа) — фаза 1 не встаёт; (2) не совпал transform-set — фаза 2 не встаёт; (3) ACL не зеркальный — трафик шифруется в одну сторону; (4) NAT конфликтует с IPsec — нужен NAT-T или deny ip в NAT ACL. Связанные темы: GRE (GRE + IPsec), NAT (NAT-T), AAA (для аутентификации). Проверка: show crypto isakmp sa (QM_IDLE — фаза 1 поднята), show crypto ipsec sa (encaps/decaps > 0 — трафик шифруется), show crypto map.

Офис 1 (192.168.1.0/24) ═══ IPsec ═══ Офис 2 (192.168.2.0/24) Router 1 ─── IKE (фаза 1) ─── Router 2 Router 1 ─── ESP (фаза 2) ─── Router 2 трафик зашифрован

 encr aes 256
 hash sha256
 authentication pre-share
 group 14
 exit
crypto isakmp key SECRET123 address 203.0.113.2
crypto ipsec transform-set TS esp-aes 256 esp-sha256-hmac
crypto map CMAP 10 ipsec-isakmp
 set peer 203.0.113.2
 set transform-set TS
 match address VPN_TRAFFIC
 exit
interface f0/1
 crypto map CMAP
 exit

QoS

QoSTrafficVoice/Video

Зачем: Приоритизация трафика. Голос и видео важнее файлов — при перегрузке канала QoS даёт им приоритет. Без QoS голос «квакает», видео «сыпется». Классификация: DSCP-метки (0–63). Голос — EF (46), видео — AF41 (34), данные — 0. CoS (L2) — 0–7, используется в 802.1Q-тегах. Очереди: LLQ (Low Latency Queue) — для голоса (строгий приоритет), CBWFQ — для остальных классов (гарантированная полоса). Policing vs Shaping: Policing — дропает лишнее (жёстко), Shaping — буферизует (сглаживает, для WAN). Trust boundary: где ставить метки DSCP? Обычно на access-порту (телефон ставит EF, ПК — 0) или на trunk между свитчами. Типичные ошибки: (1) не включили mls qos глобально — QoS не работает; (2) не настроили trust boundary — метки сбрасываются; (3) LLQ > 33% канала — голос «съедает» всё. Связанные темы: Voice VLAN, Auto-QoS. Проверка: show policy-map interface f0/1 (счётчики по классам), show mls qos (глобальные настройки).

Voice (EF 46) → Priority Queue (LLQ) — 20% Video (AF41 34) → CBWFQ — 30% Data (0) → Fair Queue — остальное
class-map match-any VOICE
 match dscp ef
 exit
policy-map WAN
 class VOICE
  priority percent 20
 class class-default
  fair-queue
 exit
interface f0/1
 service-policy output WAN
 exit
interface f0/0
 mls qos trust dscp
 exit
show policy-map interface f0/1
