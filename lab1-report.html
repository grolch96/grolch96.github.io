📘 ЛАБА 1: ПРОЕКТИРОВАНИЕ ОТКАЗОУСТОЙЧИВОЙ СЕТИ (Base Legacy)

Тема: Проектирование отказоустойчивой мультисервисной сети на базе L3-коммутации
Версия PT: Cisco Packet Tracer 6.2
Устройства: 2 × 2811 (роутеры), 5 × 3560 (L3-свитчи), 1 × 2960 (L2-свитч)

🗺️ 1. ТОПОЛОГИЯ СЕТИ

Сеть построена по трехуровневой иерархии (Ядро → Распределение → Доступ) с резервированием всех критических узлов.

  • Уровень ядра (Core): Два граничных роутера (R1, R2) обеспечивают выход в интернет (NAT) и резервирование шлюза (HSRP). Четыре L3-свитча (SW1, SW2, SW11, SW22) образуют кольцо ядра, обеспечивая высокоскоростную маршрутизацию между VLAN по OSPF.
  • Уровень распределения: Свитч SW00 (L3) и SW0 (L2) образуют периферийный сегмент, подключенный к ядру через агрегированный канал.
  • Уровень доступа: К свитчам подключены клиентские ПК и серверы, разделенные на VLAN.

🌳 1.1. STP: Кто корневой мост

В базовой лабораторной корневой мост (Root Bridge) назначен вручную через приоритет. Это делает топологию предсказуемой: весь трафик между VLAN идёт через один центральный свитч.

Устройство Приоритет STP Роль
SW1 24576 Корневой мост (Root Bridge) для всех VLAN
SW11 28672 Второй после SW1 (резерв)
SW2 36864 Резервный
SW22 45056 Резервный
SW0, SW00 32768 (по умолчанию) Не корень

Команда настройки (на SW1):

spanning-tree vlan 1,100,102-107 priority 24576

Проверка:

SW1# show spanning-tree vlan 1
  This bridge is the root

Если на другом свитче выполнить show spanning-tree vlan 1, в строке Root ID → Address будет MAC-адрес SW1 — это подтверждает, что корень именно он.

⚙️ 2. РЕАЛИЗОВАННЫЕ ТЕХНОЛОГИИ

2.1. VLAN и Trunk (Сегментация L2)

Сеть разделена на 10 логических подсетей (VLAN 1, 100, 102–108). Трафик между ними передается по магистральным каналам (Trunk 802.1Q).

Возможность: Изоляция broadcast-доменов и повышение безопасности. Клиенты VLAN 104 не видят трафик VLAN 105.

2.2. EtherChannel / LACP (Агрегация каналов)

Каналы между ключевыми свитчами агрегированы:

  • Po1: SW1 ↔ SW11 (9 портов, LACP).
  • Po2: SW0 ↔ SW00 (4 порта, PAgP).
  • Po3: SW2 ↔ SW22 (4 порта, LACP).

Возможность: Пропускная способность до 900 Мбит/с. Отказ одного кабеля не роняет канал.

Примечание: Для стабильной работы LACP в PT 6.2 на всех портах жестко заданы параметры speed 100 и duplex full.

2.3. STP / Rapid-PVST+ (Защита от петель)

Корневым мостом (Root Bridge) назначен SW1 (Priority 24576).

Возможность: Избыточные медленные порты (Fa0/4, Fa0/5 на SW22) заблокированы (Altn BLK) и работают как «спящий резерв» для защиты от broadcast-штормов.

2.4. OSPFv2 (Динамическая маршрутизация)

На всех L3-устройствах (R1, R2, SW1, SW2, SW11, SW00) настроен OSPF Area 0 с аутентификацией (MD5).

Возможность: Автоматическое построение карты сети. SW00 интегрирован в OSPF, что обеспечило связность сетей 3.0 и 5.0/6.0. Удален фантомный анонс сети 3.0 на SW2 (маршрут теперь идет через правильный шлюз).

2.5. HSRP (Отказоустойчивость шлюза)

На роутерах R1 и R2 настроен протокол HSRP (Группа 1).

  • Виртуальный IP-шлюз: 192.168.1.2.
  • R1: Active (Приоритет 150, с preempt).
  • R2: Standby (Приоритет 100).

Возможность: Если R1 сгорит, R2 мгновенно примет на себя IP 192.168.1.2, и клиенты не заметят обрыва.

2.6. NAT / PAT (Выход в интернет)

На интерфейсах Fa0/1 роутеров настроен PAT (Overload).

Возможность: Все внутренние клиенты выходят в интернет под одним внешним IP-адресом (30.30.30.31/32). Исправлена ошибка в ACL (замена host на маски подсетей).

2.7. DHCP (Автоматизация)

На L3-свитчах (SW1, SW2, SW11) подняты DHCP-серверы для своих VLAN.

Особенность VLAN 108: В связи с особенностями симулятора (broadcast-запросы не проходят через каскад из 3 L3-свитчей), DHCP-сервер для сети 8.0 перенесен на SW00. Для активации SVI Vlan108 использован порт-заглушка (Fa0/10).

🔧 3. УСТРАНЕННЫЕ ПРОБЛЕМЫ

  1. Сломанные агрегаты: Выровнены параметры портов (speed/duplex), LACP собран.
  2. Конфликт IP роутеров: Настроен HSRP, роутеры получили разные реальные адреса.
  3. Ошибка в NAT: Исправлен ACL, клиенты получили доступ в интернет.
  4. Изоляция SW00: Добавлен в OSPF.
  5. DHCP в VLAN 108: Перенесен на SW00.

🧪 4. ПРОТОКОЛ ТЕСТИРОВАНИЯ

1. Граничные роутеры (R1, R2)

Цель: Проверить HSRP, NAT, OSPF и выход в интернет.

  • На Router 1: show standby brief (Active), show ip nat translations, show access-lists NAT. Тест эстафеты: shutdown на Fa0/0.
  • На Router 2: show standby brief (Standby, после падения R1 — Active). ping 192.168.1.2 (не должен прерваться). show ip ospf neighbor (FULL).

2. Ядро L3 (SW1, SW2, SW11, SW22)

Цель: Проверить STP, EtherChannel, OSPF и отсутствие фантомных маршрутов.

  • SW1: show spanning-tree vlan 1 (This bridge is the root), show etherchannel summary (Po1 SU, P).
  • SW11: show spanning-tree vlan 1 (Po1 Root FWD), ping 192.168.3.254.
  • SW22: show spanning-tree vlan 1 (Fa0/4, Fa0/5 Altn BLK), show etherchannel summary (Po3 SU).
  • SW2: show ip ospf neighbor (FULL), show ip route 192.168.3.0 (через 192.168.1.249).

3. Периферия (SW00, SW0)

Цель: Проверить PAgP, DHCP и SVI.

  • SW00: show ip interface brief (Vlan108 и 103 up/up), show ip dhcp binding, show ip ospf neighbor (FULL).
  • SW0: show etherchannel summary (Po2 SU), show interfaces trunk (Fa0/8 trunking).

4. Клиентские ПК

Цель: Проверить, что сеть работает для пользователя.

  • ПК в сети 8.0: DHCP (IP 192.168.8.1, шлюз .254), ping 192.168.8.254 (100%).
  • ПК в сети 5.0: ping 192.168.3.254 (100%).
  • Любой ПК: ping 30.30.30.30 (100%).
